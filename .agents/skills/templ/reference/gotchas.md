# templ gotchas — read before generating Alpine.js / htmx markup

Distilled from this repo's `CLAUDE.md` (hard-won) + templ.guide. These are the **#1 source of silent bugs** in this codebase.

## Templ attribute escaping breaks Alpine.js / htmx — silently

templ's `EscapeString` converts inside HTML attributes: `"` → `&quot;`, `'` → `&#39;`, `&` → `&amp;`. This breaks Alpine `x-data` / `hx-*` JSON. **Alpine swallows the parse failure with no console error**, so the component just doesn't work.

**Symptoms:** dropdown/combobox options missing; no console errors; unit tests pass but browser fails. Check rendered HTML in devtools for `&quot;` inside `x-data`.

### Simple Alpine `x-data` (data only, no JS code)
Use unquoted JS property names, avoid quoted string literals:
```go
// GOOD — unquoted keys, nothing to escape
return fmt.Sprintf(`{ opened: [false,false], count: 0 }`)
```

### Complex Alpine (functions / strings)
Use `templ.Raw()` inside a `<script>` + `Alpine.data()` registration:
```go
func myAlpineScript(cfg Config) string {
	return fmt.Sprintf(`document.addEventListener('alpine:init', () => {
		Alpine.data('myComponent', () => ({
			value: '%s',
			doThing() { htmx.ajax('GET', '/api/data', {target: '#target'}); }
		}));
	});`, cfg.DefaultValue)
}
```
```templ
templ myScript(cfg Config) {
	@templ.Raw("<script>" + myAlpineScript(cfg) + "</script>")
}
// reference with: <div x-data="myComponent">
```

### Or use templ's own helper
For pure data into an attribute, `templ.JSONString(data)` is the sanctioned path (`x-data={ templ.JSONString(data) }`).

## NEVER `json.Marshal` into an HTML attribute via templ

`json.Marshal` produces double-quoted strings; templ escapes the quotes; Alpine sees broken syntax. Use single-quoted JS string builders:
```go
func optionsToJS(options []Option) string {
	result := "["
	for i, opt := range options {
		if i > 0 { result += "," }
		result += fmt.Sprintf("{value:'%s',label:'%s'}",
			jsEscapeSingle(opt.Value), jsEscapeSingle(opt.Label))
	}
	return result + "]"
}
```

## Null arrays crash Alpine

`json.Marshal([]string(nil))` → `null`, not `[]`. Alpine `selectedValues.includes(...)` throws on null. Guard:
```go
if string(selectedJSON) == "null" {
	selectedJSON = []byte("[]")
}
```

## Generated files — never hand-edit

`*_templ.go` is regenerated by `templ generate`; `assets/styles.css` by Tailwind. Edit the `.templ` / CSS source instead. On merge conflicts, resolve the `.templ` source then regenerate — never hand-resolve generated files.

## Regeneration quirks

- `templ generate` sometimes reports "0 updates" even when source changed.
- Force: `rm components/<name>/<name>_templ.go && templ generate`.
- If rendering looks wrong, inspect the generated `_templ.go`.
- Use `templ.Attributes` (a `map[string]any`) for dynamic attribute maps.

## Variable inside `<script>`/`<style>` body is rejected

templ's injection guard forbids variables in those tag bodies. Pass data via attribute / `templ.JSONScript` / `{{ }}` interpolation / `script` template (see components.md + security.md).

## Tags must close

Every element needs a closing or self-closing tag — templ won't infer it. Void elements (`<img/>`, `<br/>`) self-close in source but render without the slash.
