# Consumer-local icon packs

`iconpack` generates an attributed SVG sprite and typed Go component package in
a consumer-owned directory. It does not add selected icons to Goshtoso's
embedded Heroicons package. Consumers choose assets by exact Arai Hu Assets
catalog canonical name, including literal mixed-case names such as
`brand-developer-icons-tRPC`.

The input must be either an extracted release root or a release archive. A
Goshtoso checkout, GitHub source archive, `internal/acquisition/vendor` tree, or
other source directory is not a release boundary and is rejected by its
structure, not by the names of its parent directories. A verified release may
therefore be stored below a consumer path such as `internal/`, `vendor/`, or
`acquisition/`; only the selected root's checkout markers, pinned release files,
and checksummed inventory determine its boundary. Generation requires
separately pinned SHA-256 values for `catalog.json`, `release.json`, and
`checksums.txt`; archive mode also requires the archive SHA-256. The command
verifies every checksums record, release inventory entry, selected artifact,
namespace/product allowlist, and exact source-sprite symbol before writing.
Release-root reads are descriptor-relative and reject symbolic links, special
files, and non-directory parents. Verified release files are captured once;
later source-tree mutation cannot change generated bytes.

## Exact-name selection

The release workflow uses the immutable, publicly released Arai Hû Assets
`v0.2.0` archive. The hashes below are the verified published values. They
identify Assets, not the Goshtoso release. During local development run
`go run ./cmd/iconpack`. After the Goshtoso `v0.2.0` tag is public, consumers
should pin the generator to
`github.com/araihu/goshtoso/cmd/iconpack@v0.2.0`.

```bash
# Assets v0.2.0 is public; use this after the Goshtoso v0.2.0 tag is public:
go run github.com/araihu/goshtoso/cmd/iconpack@v0.2.0 \
  -release-archive /path/to/araihu-assets-v0.2.0.tar.gz \
  -archive-sha256 5d7d691e22d4071507b0bf2248713d7008adf57c18840cfd46e20901db0b78e5 \
  -release v0.2.0 \
  -catalog-sha256 a0e8e5c8928e37de979ce9a60f3d66fad1aa1b4c7d2904f9275f0be9932a33d6 \
  -release-json-sha256 77c696ae5eceb5e7bc11d19affb7c2c7b7e8afc6414882b9b059239e315f2260 \
  -checksums-sha256 334005c77622250a1e827b9472161cd6e56c82d487fc0d44023d49261f8dbee5 \
  -name brand-developer-icons-tRPC \
  -name ui-hi-16-solid-check \
  -out ./internal/appicons \
  -package appicons \
  -const-prefix Icon \
  -sprite-url /assets/icons/app.svg
```

Use `-release-root /path/to/extracted-release` instead of `-release-archive`
and `-archive-sha256` for a verified extracted root. The output parent must
already exist. The immutable published archive URL is
`https://github.com/araihu/assets/releases/download/v0.2.0/araihu-assets-v0.2.0.tar.gz`.
Run the archive and extracted-member verification documented by
[Arai Hû Assets](https://github.com/araihu/assets/blob/v0.2.0/docs/integration/consumers.md)
before invoking the generator.

## Find canonical names

Read `catalog.json` from the verified Assets release root. The generator
allowlist currently includes the `ui/heroicons` and `brand/developer-icons`
families. Select the catalog's exact `canonicalName`; do not lowercase it or
derive it from a file name. The mixed-case entry
`brand-developer-icons-tRPC` is intentionally preserved.

```bash
jq -r '.assets[] | select((.namespace == "ui" and .product == "heroicons") or (.namespace == "brand" and .product == "developer-icons")) | .canonicalName' \
  /path/to/release-root/catalog.json
```

## Selection manifest

JSON is the canonical manifest form:

```json
{
  "schemaVersion": 1,
  "names": [
    "brand-developer-icons-tRPC",
    "ui-hi-16-solid-check"
  ]
}
```

Pass it with `-manifest ./icons.json` instead of repeated `-name` flags. For a
small one-off selection, repeated `-name` flags are also supported; the two
selection modes are mutually exclusive. YAML with identical field names is
accepted for compatibility:

```yaml
schemaVersion: 1
names:
  - brand-developer-icons-tRPC
  - ui-hi-16-solid-check
```

## Output contract

One successful publication creates the requested directory atomically with:

- `sprite.svg`: only selected `<symbol>` elements, using catalog
  `spriteSymbol` values literally.
- `icons_gen.go`: typed canonical names, `icon.Symbol` bindings, lookup data,
  and a consumer-local `Icon` component bound to the selected sprite URL.
- `manifest.json`: release, catalog, selected-asset, generated-identifier, and
  output-file identities.
- `provenance.json` plus `PROVENANCE/*.json`: selected and release-authored
  upstream provenance.
- `LICENSES/*.txt` and `NOTICE`: exact verified attribution bytes.

The public and generated API uses generic names such as `Name`, `Glyph`,
`Config`, `Lookup`, and `Icon`. Only Go identifiers are normalized;
`CanonicalName` and manifest values preserve catalog bytes exactly.

Publication uses a sibling lock and same-parent staged directory. An absent
destination is published with one directory rename. An identical owned output
is idempotent. A changed, symlinked, non-owned, or unrelated destination is
never replaced. Use `-check` in CI to verify an existing output byte-for-byte.

## Serve and render the pack

The `-sprite-url` value is the public URL of the generated `sprite.svg`. If the
output directory is `internal/appicons`, serve that file at the same URL before
rendering a generated symbol:

```templ
import "example.com/application/internal/appicons"

@appicons.Icon(appicons.Config{
    Symbol: appicons.IconBrandDeveloperIconsTRPC,
    Label:  "tRPC",
})
```

The generated component uses the catalog-declared `devicon-trpc` symbol while
the Go identifier is normalized separately. Keep `NOTICE`, `LICENSES/`, and
`PROVENANCE/` with the distributed generated package. `manifest.json` records
the identities of every other generated output; it does not hash itself.

## Update a pack

Changing the selected names, Assets release, or output options changes the
consumer-owned identity. Because publication refuses a different-byte existing
directory, generate into a new versioned directory first, run `-check` and the
consumer tests, then switch the application URL deliberately. Replace an
existing directory only through the documented reviewed replacement procedure;
never delete or overwrite a directory to make a failed generation appear
successful.

## External consumer proof

The proof script extracts the verified release archive into a private temporary
boundary, generates a separate Go module, builds it, renders the generated
component, and checks the literal `devicon-trpc` reference:

```bash
./scripts/iconpack-consumer-proof.sh \
  /path/to/araihu-assets-v0.2.0.tar.gz \
  5d7d691e22d4071507b0bf2248713d7008adf57c18840cfd46e20901db0b78e5
```

The temporary consumer replaces Goshtoso only as its Go dependency so an
uncommitted producer can be tested. All icon inputs still come exclusively from
the verified release archive; no Goshtoso checkout or vendored asset tree is an
icon source.
